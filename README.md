# 明一把 · PUBG PROGUESS

明一把（PUBG PROGUESS）是一款面向绝地求生赛事爱好者的网页小游戏。你可以在全明星或 PCL 题库中，通过国籍、赛区、战队、年龄等线索，在 8 次机会内猜出目标选手；也可以挑战选手九宫格，用转会经历寻找战队之间的交集。网站还提供选手资料查询、2026 赛事数据筛选与排序，支持手机和电脑、浅深色风格切换及本地进度保存。无需登录，打开网页即可体验。

## 在线体验

[立即游玩明一把](https://pubg-pro-guess.pages.dev/)

## 主要功能

- **猜选手**：全明星与 PCL 两种题库，每局 8 次机会，通过颜色和数值方向提示逐步锁定答案。
- **选手九宫格**：根据选手历史效力战队填满九宫格，支持转会挑战和自定义题目，默认使用 PCL 题库。
- **选手资料**：搜索选手 ID、国籍、赛区或战队，查看基础资料与已收录的赛事表现。
- **赛事数据**：按战队或关键词筛选，点击表头排序；手机端以紧凑连续表格展示，固定表头与选手名列。
- **界面与存档**：支持柔和桌面、沉浸深色两种风格，提供输入联想、动画设置，并在当前浏览器保存对局与战绩。

## 选手九宫格

左侧栏「选手九宫格」在主站中央内嵌运行，首次进入默认使用 PCL 题库，也可手动切换到全球题库。随机出题统一使用转会挑战，保留自定义题目、11 次机会、计分和生涯战绩。旧普通挑战对局首次被替换时会另存为浏览器本地备份。玩法规则在游戏顶部。主站深浅色、沉浸风格会同步到九宫格。独立打开链接保留原独立页面。

项目内 `grid/` 是桌面原文件夹的站点副本，原文件夹保持不变。两个游戏使用不同存档键；浏览器存档仍按域名、端口和浏览器区分。

网页题库为只读。维护者可在项目内更新 `grid/data/` 中相应题库的 JSON 和 JS 文件，再重新发布。

战队简称已统一为 AG(泰国)、QAD、FIUM、GP、LGCY、MAG，对应旧 AGT、AQ、FIU、GPT、LEG、MG。唐山战队统一为 TSG(新)，兼容旧 TSG-TS 引用，与原 Triumphant Song Gaming（TSG）分开。选手历任战队、图标关联与两套 JSON/JS 题库同步更新。`grid/team-renames.js` 在启动时仅迁移已识别的旧战队身份；浏览器旧题库与对局会先保留改名前备份，已有答案、次数、分数、自定义记录与生涯战绩继续保留。出现与自定义战队 ID 冲突时保留原数据，不猜测合并。Type、Heather 和 DIEL 的 GAME PT 履历均使用 GP。

VC Gaming 与 VC(越南) 分别保留，各自使用对应队标。原 VC 选手的历史队伍不变，不根据队标或国籍猜测新的效力关系。Xavage Men Esports 统一为 XMEN，兼容旧 XME。队标文件名支持中文和括号，仍禁止绝对路径、外部网址和目录穿越。选手 ID 仅大小写变化时，已保存答案会匹配当前题库中的 ID。

原桌面文件夹后续的修改不会自动同步到此副本。维护此站时编辑 `grid/` 中对应文件，再重新构建、上传。运行 `node tools/grid-embed-check.js` 检查导航、主题、响应式、完整答题、刷新存档、题库切换及自定义题目。

## 本地预览

安装 Node.js 后，在项目目录运行 `node tools/serve.js`，打开 http://127.0.0.1:8080 。预览服务器只监听本机，不需要安装依赖。不要直接双击 HTML，浏览器可能阻止读取选手数据库。

也可以运行 `npm start`。设置 `PORT` 环境变量可更换端口。

## 玩法与查询

- 绿色表示相同，黄色表示接近，灰色表示不同或未知。年龄相差不超过 3 岁、PGC 次数相差不超过 2 次、冠军数相差 1 次时显示黄色。
- 数值后的 ↑ 表示答案更大，↓ 表示答案更小。国籍不同而赛区相同时，国籍显示黄色。
- 重复猜测不消耗机会；查看答案会结束本局并清零连胜。结束后仍可再次查看答案。
- 输入框支持方向键选候选、回车选择或提交、Esc 关闭候选。弹窗支持 Esc 关闭。
- 猜对后，遮罩与弹窗先淡入、轻移，随后选手资料卡以小角度旋转入场、略微放大后落稳；关闭交互动画或开启系统减少动态效果时直接显示。动效中仍可关闭弹窗或开始新一局，不改变计分与存档。运行 `node tools/result-motion-check.js` 可验证两种模式与风格、手机适配、旋转放大、键盘焦点和快速关闭重开。
- 查询页支持 ID、国籍、赛区、战队、PGC 次数，显示全部匹配结果。数字 ID 精确匹配优先；例如 `129` 查询该选手，`17` 可查战队。输入 `pgc:2` 可精确查询 PGC 出场 2 次的选手。
- 数据页的“国际KD”使用现有数据口径：总淘汰 ÷ 国际场次。火力值沿用 JSON 中已有值，未重新计算。
- 顶部“显示偏好”提供深色外观、输入联想与交互动画三个独立开关。切换时，邻近开关只产生短暂涟漪和轻移，状态不会改变；偏好会自动保存。支持触屏与键盘，系统开启减少动态效果或手动关闭交互动画时停用动效。

## 数据和存档

选手资料与结果弹窗包含 **2026 赛事表现**：场均淘汰（赛事表中的国际 KD）、场均伤害、各指标的排名百分比与个人均值差异，以及国际场次、总淘汰、总伤害和火力值。数据直接读取 `data/kd2026.json`，按去除首尾空格且忽略大小写的选手 ID 精确关联；更新该文件后刷新页面即可同步。

每项指标单独降序排名，并列同名次；“前 X%”为排名除以有效样本人数后向上取整。平均值为库内有国际场次且该项指标有效的选手的个人指标算术平均，不是按场次加权；条形展示排名位置，不代表逐场趋势。暂无赛事数据、零场次或缺失指标会明确说明，不补造零值或走势图。赛事加载失败不会阻止游戏及资料查询，可在资料卡中单独重试。

场均淘汰或场均伤害任一项排名前 20 的选手，资料卡与结果弹窗会显示对应 `TOP20` 标记和动态金色边缘光效；两项独立判定，并列第 20 名也包含在内。关闭“显示偏好 → 交互动画”或启用系统减少动态效果后，保留静态金色边缘。

- `data/playerDB.json`：全明星选手库。
- `data/pclDB.json`：PCL 选手库。
- `data/kd2026.json`：世界赛统计数据。
- 两种模式共用 `js/core.js`、`js/storage.js` 和 `js/render.js`，通过页面 `data-game-mode` 选择数据和存档前缀；共用工具位于 `js/utils.js`。
- 旧存档会自动迁移；已结束对局不会重新累计胜利。新对局按开局日期计算年龄，刷新和跨生日恢复时保持一致；没有生日的选手沿用已有固定年龄。
- 浏览器存储被禁用时，游戏仍可运行，但刷新后无法恢复进度。图片缺失时使用本地占位图。

## 战队队标

`images/teams/` 中的队标已用于猜测记录、输入联想、选手资料（含结果弹窗）和赛事数据表。队标与队名一起显示，保持原始比例，兼容两种风格与深浅色外观。`Tianba` 对应 `TIAN.png`；缺少对应文件的队伍只显示队名，图片加载失败也会自动退回文字。

队标匹配集中在 `js/utils.js` 的 `teamLogoFiles` 与 `teamAliases`。新增队伍时，将 PNG 放进 `images/teams/`，并将不含扩展名、大小写一致的文件名加入 `teamLogoFiles`；队名与文件名不同时，在 `teamAliases` 增加小写别名。匹配不改变数据库队名或游戏判定，也不沿用可能错配的旧 `teamImage`。使用 Live Server 刷新即可预览；部署 `dist/` 前重新构建。

运行 `node tools/team-logos-check.js` 可验证队标在源码与部署版中的显示、风格适配、手机布局及缺图回退；Playwright 配置方式同下文浏览器检查。

## 检查和部署

上传 Cloudflare Pages 的具体操作见 [CLOUDFLARE.md](./CLOUDFLARE.md)。运行 `npm run build` 后执行 `npm run release:check`，核对发布文件数量、大小、资源大小写和数据同步。只上传 `dist` 的内容或已生成的 `PUBGPROGUESS-cloudflare.zip`。


运行 `node --test tests/*.test.js` 或 `npm test` 检查游戏规则、存档和查询。

运行 `npm install --ignore-scripts`（或 `pnpm install --ignore-scripts`），再运行 `node tools/build.js` 或 `npm run build`。部署时上传 `dist/` 的内容。构建先在临时目录完成混淆，成功后替换 `dist/`；缺少依赖或混淆失败时保留已有构建。`npm run build:watch` 监听页面、脚本、样式、数据和图片变化。

可选的真实浏览器检查：安装 Playwright 并确保 Microsoft Edge 可用后，运行 `node tools/browser-check.js`。也可以通过 `PLAYWRIGHT_MODULE_DIR` 指定已有 Playwright 包所在的目录，通过 `BROWSER_CHANNEL` 选择浏览器。检查同时覆盖源码和 `dist/`，因此先完成构建。

运行 `node tools/preferences-check.js` 可单独验证显示偏好的涟漪反馈、开关独立状态、偏好记忆、触屏与键盘操作，以及系统减少动态效果设置。

## 界面与适配

主站页面支持短促的切页模糊拖影：原生跨文档 View Transitions 在旧、新画面间交叉淡入淡出，伴随轻微平移与模糊；浏览器不支持或跳过原生过渡时使用轻量入场动画。正常链接、后退、刷新和存档保持原有行为。关闭交互动画或启用系统减少动态效果时跳过；快速再次操作会结束当前动画。`css/navigation.css`、`js/navigation.js` 负责效果，运行 `node tools/navigation-motion-check.js` 验证原生截图动画、兼容入场、手机/桌面、后退、存档和动效开关。

页面使用白色主面板、浅灰背景、柔和蓝色主操作和薄荷绿、淡紫点缀。桌面采用窄侧栏与居中的内容工作区，猜测线索和输入框沿中央轴对齐；输入框使用大圆角与细边框强调，规则收在下方可展开区域，重开和查看答案作为次级操作。资料查询使用同样的居中搜索框，赛事页保留行式数据与筛选。平板侧栏缩成图标导航，笔记本短屏减少纵向留白。手机端（宽度不超过 768px）采用固定单屏：猜测记录以紧凑行连续显示，每次猜测一行、保留八项线索和队标；统一表头，去掉记录分页，短屏记录多时仅在记录区域纵向滚动；资料查询采用逐位查看；赛事页使用紧凑连续表格，表格内支持上下浏览名单、左右查看指标，固定表头与选手名列，点击表头排序。资料卡分为资料、表现、汇总与口径四页，规则与设置采用分区显示。模糊联想结果和较多的猜测记录可以在各自区域纵向滚动。手机键盘弹出时保留输入框上方的历史选手与线索，候选列表在输入框下方展示。横屏使用紧凑分栏，深色外观和减少动态效果偏好继续可用。

在任意页面打开 **显示偏好 → 界面风格**，可在 **柔和桌面** 与 **沉浸深色** 之间切换。沉浸风格使用黑色底层、深灰面板、局部标题渐变和绿色主要操作；选择会自动保存，刷新和切换页面后继续生效。沉浸风格固定为深色，因此外观开关暂时不可操作；切回柔和桌面时，会恢复此前的深浅色选择。切换只影响外观，不修改对局、战绩、联想或动画偏好。

两种风格共用相同页面和游戏逻辑。`css/local.css` 保留柔和桌面与公共组件，`css/immersive.css` 中的沉浸样式全部限定在 `data-style="immersive"` 下；`js/theme.js` 在首屏渲染前恢复选择。

运行 `node tools/ui-check.js` 可检查四个页面在 320、390、768、1024、1440 像素宽度下的布局，并验证猜测、弹窗、输入和线索分页。运行 `node tools/mobile-check.js` 可检查源码与发布版的 320×568、390×844、768×1024、568×320、844×390 布局、两种风格、完整资料分区、八次猜测存档、桌面恢复、搜索筛选排序，以及键盘缩小／平移可视区域模拟。检查将截图保存在 `.checks/mobile-*.png`；实际 iOS/Android 键盘仍建议真机体验。

运行 `node tools/style-check.js` 可验证沉浸风格、柔和风格偏好恢复、风格切换前后的存档一致性、文字对比、手机触屏及键盘选择，并在 `.checks/immersive-*.png` 保存截图。

运行 `node tools/event-stats-check.js` 可检查赛事资料在两种风格、深浅色与 320/390/768/1440 像素宽度下的显示，以及多结果查询、游戏结果弹窗、键盘焦点、缺数据、失败重试和延迟加载；截图保存在 `.checks/event-stats-*.png`。
